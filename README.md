# depviz — визуализация графа зависимостей Cargo

Учебный инструмент (вариант №5): по имени и версии Rust-пакета строит граф
его зависимостей, ищет обратные зависимости и рисует граф через Graphviz.
Всё написано на Python 3.9+ **только на стандартной библиотеке**: менеджеры
пакетов (`cargo`, `pip`) и сторонние библиотеки для получения зависимостей
не используются. Работает на Windows (x86/x64), macOS (Intel и Apple Silicon),
Linux.

## Как это работает

1. Настройки читаются из YAML-файла (свой мини-разборщик, без PyYAML).
2. Данные берутся из **индекса реестра Cargo** (sparse index, например
   `https://index.crates.io`): для пакета скачивается файл с JSON-строками —
   по строке на версию, внутри список зависимостей. Версия зависимости
   выбирается по требованию (`^1.2`, `~0.3`, `>=1, <2`, `1.*`) — разбор
   требований реализован в `semver.py`.
3. Граф строится обходом в ширину (BFS, без рекурсии) с ограничением глубины
   и защитой от циклов.
4. Граф выводится текстом, как обратные зависимости или как диаграмма
   Graphviz (DOT) + картинка.
5. Тестовый режим позволяет работать без интернета: граф берётся из файла,
   где пакеты названы большими латинскими буквами.

## Настройки (YAML)

| Параметр | Обязателен | Описание |
| --- | --- | --- |
| `package_name` | да | имя пакета (в режиме `test` — большие латинские буквы) |
| `repository` | да | URL индекса (`remote`) или путь к тестовому файлу (`test`) |
| `repo_mode` | да | `remote` — настоящий репозиторий, `test` — файл |
| `package_version` | для `remote` | точная версия `1.2.3` |
| `max_depth` | да | максимальная глубина анализа, целое ≥ 1 |
| `mode` | нет (`graph`) | `params`, `direct`, `graph`, `reverse`, `visualize` |
| `reverse_target` | для `reverse` | пакет, чьи обратные зависимости ищем |
| `dot_file` | нет (`out/graph.dot`) | куда сохранить описание Graphviz |
| `image_file` | нет (`out/graph.png`) | куда сохранить картинку (`png`, `svg`, `pdf`) |
| `show_image` | нет (`true`) | открыть картинку после построения |

Неизвестные параметры, пустые значения, неверные типы, отсутствующие файлы,
неверные URL и версии приводят к понятному сообщению `Ошибка: ...`.
Коды завершения: `0` — успех, `2` — ошибка настроек, `3` — ошибка
репозитория (нет сети, пакета, версии, битый файл), `4` — ошибка рисования.

## Режимы работы (этапы)

| `mode` | Этап | Что делает |
| --- | --- | --- |
| `params` | 1 | печатает все настройки в формате «ключ: значение» |
| `direct` | 2 | печатает прямые зависимости пакета |
| `graph` | 3 | строит граф (BFS, глубина, циклы), печатает уровни и рёбра |
| `reverse` | 4 | печатает пакеты, которые зависят от `reverse_target` |
| `visualize` | 5 | пишет `.dot`, рисует картинку и открывает её |

Правила выбора зависимостей: учитываются обычные и build-зависимости;
`dev`-зависимости и необязательные (`optional`) пропускаются; отозванные
(`yanked`) версии не выбираются; пре-релизы выбираются только если
требование их явно содержит.

`max_depth` ограничивает и построение графа, и обратный обход: в режиме
`reverse` сначала строится граф от `package_name` на `max_depth` уровней,
затем по развёрнутым рёбрам ищутся зависящие от `reverse_target` пакеты.

### Формат тестового репозитория

```
# комментарий
A: B C      # A зависит от B и C
B: D
D:          # D ни от чего не зависит
```

Имена — только большие латинские буквы; зависимости через пробел или запятую;
пакет, упомянутый только как зависимость, считается пакетом без зависимостей.

## Установка и запуск

Нужен Python 3.9+ (на macOS и Windows подходят установщики с python.org,
в том числе для Apple Silicon). Для красивой картинки желательно поставить
Graphviz (`brew install graphviz` / `winget install Graphviz.Graphviz`);
без него программа нарисует граф встроенным SVG-рисовальщиком.

Сборки нет (интерпретируемый язык). Запуск:

```
# macOS / Linux
./run.sh examples/test_acyclic.yaml
# Windows
run.bat examples\test_acyclic.yaml
# везде
python3 src/main.py examples/test_acyclic.yaml
make run CONFIG=examples/test_acyclic.yaml
```

Запуск тестов:

```
./run.sh test        # macOS / Linux
run.bat test         # Windows
python3 -m unittest discover -s tests -t . -v
make test
```

На macOS при установке Python с python.org один раз выполните
`Install Certificates.command` (папка `/Applications/Python 3.x`), иначе
HTTPS-запросы к реестру завершатся ошибкой сертификата.

## Примеры использования

Тестовый репозиторий (`tests/data/acyclic.txt`), `mode: graph`:

```
Узлы по уровням:
  Уровень 0: A
  Уровень 1: B, C
  Уровень 2: D, E
  Уровень 3: F
Рёбра (пакет -> его зависимость):
  A -> B
  A -> C
  B -> D
  C -> D
  C -> E
  D -> F
  E -> F
Циклических зависимостей нет.
```

Цикл (`tests/data/cyclic.txt`, `mode: graph`): рёбра `A -> B`, `B -> C`,
`C -> A` помечаются как циклические, обход не зацикливается.

Обратные зависимости (`examples/test_complex_reverse.yaml`): от `D` зависят
`B`, `C` (уровень 1) и `A` (уровень 2).

Визуализация (`mode: visualize`, `examples/test_cyclic.yaml`):

```
digraph "A" {
  rankdir=LR;
  node [shape=box];
  "A" [style=filled, fillcolor=lightblue];
  "A" -> "B" [color=red];
  "B" -> "C" [color=red];
  "C" -> "A" [color=red];
  "C" -> "D";
}
```

Три настоящих пакета: `examples/real_serde_json.yaml`,
`examples/real_regex.yaml`, `examples/real_log.yaml` (нужен интернет;
при необходимости поправьте версии на существующие в crates.io).

## Сравнение со штатным инструментом (`cargo tree`)

Методика: для пакета из примера создать пустой проект с `cargo new demo`,
добавить зависимость `cargo add serde_json@=1.0.120`, выполнить
`cargo tree -p serde_json` (при необходимости `--depth N`,
`-e normal,build`) и сравнить с выводом `mode: graph` нашей программы.

Возможные расхождения и их причины:

- `cargo tree` использует `Cargo.lock` и **одну** версию на semver-диапазон
  по всему проекту; depviz выбирает для каждого требования самую новую
  подходящую версию независимо — версии могут отличаться.
- `cargo tree` учитывает включённые features и платформу (`target`-зависимости
  чужих платформ скрыты); depviz не вычисляет features и показывает
  зависимости независимо от платформы, но пропускает `optional`.
- `cargo tree` помечает повторы `(*)` и не раскрывает их повторно; depviz
  показывает каждый пакет один раз как узел, а повторы — как рёбра.
- `cargo tree` по умолчанию показывает и dev-зависимости корневого пакета;
  depviz их не учитывает.

Результаты на реальных пакетах нужно получить на своей машине с интернетом
и установленным Rust; здесь они не приводятся.
